# Multi-Agent AI Research & Decision System

A multi-agent AI system built with **LangGraph, Python, and GPT-6 Luna**. The system dynamically selects specialized agents, executes tasks in parallel, validates their outputs through a critic agent, and performs iterative revision before generating the final response.

## Overview

This project demonstrates how multiple specialized AI agents can collaborate to solve complex tasks instead of relying on a single LLM call.

The system uses a **supervisor-based architecture** where the supervisor analyzes the user's request and dynamically selects the agents required for the task.

## Agents

### Supervisor

Analyzes the user request and creates an execution plan.

It dynamically determines which specialized agents are required.

### Researcher

Handles research-oriented tasks and can interact with the search tool interface.

### Analyst

Performs reasoning and analytical operations and can use the calculator tool when required.

### Specialist

Provides additional domain-focused reasoning when the supervisor determines that a specialized perspective is useful.

### Critic

Reviews the outputs generated by the other agents and determines whether the result should pass or undergo revision.

### Revision

Improves the agent outputs based on the critic's feedback.

### Writer

Combines the validated outputs into the final response for the user.

## How It Works

### 1. User Query

The user submits a task to the system.

### 2. Supervisor Planning

The supervisor creates an execution plan and selects the agents required for the task.

### 3. Parallel Execution

Selected specialized agents execute their tasks using shared LangGraph state.

### 4. Critic Validation

The critic evaluates the collected outputs.

```text
PASS
  ↓
Writer

REVISE
  ↓
Revision Agent
  ↓
Critic
```

The revision cycle is limited to prevent uncontrolled execution loops.

### 5. Final Generation

Once the critic approves the result, the writer generates the final response.

### 6. Execution Tracking

The system records:

- Session ID
- Agent executed
- Execution status
- Timestamp
- Agent output
- Errors
- Revision count

SQLite is used to persist session and execution information.

## Design Principles

### Specialized Agents

Each agent has a focused responsibility instead of asking one LLM to perform every task.

### Dynamic Routing

The supervisor decides which agents are necessary for each query.

### Shared State

LangGraph state allows information produced by one agent to be passed to other agents.

### Validation Before Generation

The critic validates the intermediate results before the writer produces the final response.

### Controlled Iteration

Revision loops are bounded to prevent infinite agent execution.

### Persistent Execution History

SQLite stores session and agent execution information for later inspection.
